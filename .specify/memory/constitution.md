# LearnFlow Hackathon III Constitution

## Core Principles

### I. Skills-First Development

Every deliverable MUST originate from a SKILL.md + scripts/ pattern.
No application code is written manually; all code is generated by AI agents
(Claude Code, Goose) instructed by skills.

- SKILL.md MUST remain ≤ ~150 tokens (instructions only).
- Heavy logic MUST live in `scripts/` — executed, never loaded into context.
- REFERENCE.md (deep docs) MUST be loaded only on-demand, not at startup.
- A skill is considered complete only when a single prompt causes the agent to
  execute the skill autonomously from start to verified completion.
- Skills are the primary deliverable; the LearnFlow app is evidence they work.

### II. MCP Code Execution Pattern

MCP server interactions MUST be wrapped in scripts that execute server logic
client-side, returning only minimal results to the agent context window.

- Direct MCP tool calls that dump full datasets into context are PROHIBITED.
- Scripts MUST filter/process data before printing output.
- Target: 80–98% token reduction vs. direct MCP calls.
- Pattern: SKILL.md (~100 tokens) → scripts/*.py executes → "✓ Done" (~10 tokens).
- Any new MCP integration MUST demonstrate token budget before merge.

### III. Cross-Agent Compatibility (NON-NEGOTIABLE)

Every skill MUST work identically on Claude Code, Goose, and OpenAI Codex
without modification.

- Skills MUST be stored in `.claude/skills/<skill-name>/SKILL.md`.
- YAML frontmatter MUST include `name` and `description` fields.
- No agent-specific directives inside SKILL.md (no `claude:`-only syntax).
- Cross-agent test: same prompt on Claude Code AND Goose MUST produce the
  same output before a skill is considered production-ready.

### IV. Cloud-Native Architecture

All services MUST be stateless, containerized, and deployed on Kubernetes.

- Services MUST use Dapr sidecars for state, pub/sub, and service invocation.
- Asynchronous communication MUST use Apache Kafka topics.
- Synchronous service-to-service calls MUST go through Dapr service invocation.
- Secrets MUST NOT be hardcoded; use Kubernetes Secrets or `.env` files only.
- Every service MUST have a Dockerfile and a Kubernetes manifest (Deployment +
  Service, or Helm chart).
- Health checks (liveness + readiness probes) MUST be defined for every pod.

### V. Spec-Driven Development (SDD)

All work MUST follow the pipeline:
**Constitution → Spec → Plan → Tasks → Skill/Code Implementation**.

- Each hackathon phase MUST have its own folder: `specs/<phase-name>/`.
- No implementation begins without an approved spec.md AND plan.md.
- tasks.md MUST reference spec user stories (US1, US2 …) for traceability.
- PHRs MUST be created after every significant user prompt (per CLAUDE.md).
- ADR suggestions MUST be surfaced for architecturally significant decisions.

### VI. Agentic Autonomy

The gold standard for every skill is:
**single prompt → agent loads skill → script executes → minimal result → done**.

- Skills MUST achieve zero manual intervention to be considered complete.
- Any step requiring a human to run a command manually is a skill defect.
- Commit messages in learnflow-app MUST record which agent and skill produced
  the change (e.g., `Claude: deployed Kafka via kafka-k8s-setup skill`).
- Evaluation: judges MUST be able to wipe the cluster and re-deploy everything
  using only skill-driven prompts.

### VII. Separation of Concerns

Two repositories MUST remain strictly separated:

- **skills-library**: contains SKILL.md files, scripts/, REFERENCE.md, and
  skill-level tests only. No application business logic.
- **learnflow-app**: contains application code generated BY agents USING skills.
  No SKILL.md files (skills are referenced, not duplicated).
- A skill MUST NOT embed application-specific configuration; use parameters or
  environment variables instead to keep skills reusable across projects.

## Technology Stack

| Layer          | Technology                              |
|----------------|-----------------------------------------|
| Orchestration  | Kubernetes (Minikube local, cloud prod) |
| Packaging      | Helm charts                             |
| Messaging      | Apache Kafka (Bitnami Helm)             |
| Runtime sidecar| Dapr                                    |
| Backend        | FastAPI (Python 3.12)                   |
| Frontend       | Next.js 14 + Monaco Editor             |
| Database       | PostgreSQL (Neon for cloud)             |
| API Gateway    | Kong API Gateway on Kubernetes          |
| AI context     | MCP Servers (code-execution pattern)    |
| CI/CD          | GitHub Actions + Argo CD (GitOps)       |
| Docs           | Docusaurus (deployed via skill)         |
| Agents         | Claude Code + Goose (AAIF standard)     |

All infrastructure provisioning MUST be performed via Helm skills.
No `kubectl apply` of raw YAML without a wrapping skill script.

## Development Workflow & Quality Gates

### Phase Execution Order

```
Phase 1 (Foundation)  → agents-md-gen, k8s-foundation skills
Phase 2 (Infra)       → kafka-k8s-setup, postgres-k8s-setup skills
Phase 3 (Backend)     → fastapi-dapr-agent skill (7 services: 6 AI agents + code-sandbox)
Phase 4 (Frontend)    → nextjs-k8s-deploy skill
Phase 5 (Integration) → mcp-code-execution skill
Phase 6 (Docs)        → docusaurus-deploy skill (8 skill pages)
Phase 7 (LearnFlow)   → Full app built using ALL skills
Phase 8 (Polish)      → Demo, docs complete, submission ready
Phase 9 (Cloud)       → Azure / Google / Oracle Cloud deployment
Phase 10 (CD)         → Argo CD + GitHub Actions pipeline
```

Each phase folder: `specs/<phase-name>/` containing spec.md, plan.md, tasks.md.

### Quality Gates (MUST pass before merge)

1. **Skill Gate**: SKILL.md ≤ 150 tokens; scripts/ do all heavy lifting.
2. **Autonomy Gate**: Single prompt completes skill on both Claude Code & Goose.
3. **Token Gate**: Verify MCP script pattern reduces context by ≥ 80%.
4. **K8s Gate**: All pods reach `Running` state; health probes pass.
5. **Arch Gate**: No hardcoded secrets; stateless services; Dapr patterns correct.
6. **SDD Gate**: spec.md → plan.md → tasks.md chain complete before coding.

### Commit Convention

```
<Agent>: <action> using <skill-name> skill
Claude: deployed Kafka using kafka-k8s-setup skill
Goose:  scaffolded triage service using fastapi-dapr-agent skill
```

## Governance

This constitution supersedes all other practices in this project.
All pull requests MUST verify compliance with the seven core principles.

**Amendment procedure**:
1. Propose amendment in a PHR (stage: `constitution`).
2. Bump version per semantic rules (MAJOR/MINOR/PATCH).
3. Update this file and run propagation checklist (templates, READMEs).
4. Record `LAST_AMENDED_DATE` as the date of change.

**Compliance review**:
- Every spec, plan, and task list MUST include a "Constitution Check" section.
- Complexity deviations MUST be logged in the plan's Complexity Tracking table
  with a justification accepted by the project lead.
- Skill definitions that violate Principle I or II MUST be rejected at review.

**Version policy**: MAJOR.MINOR.PATCH
- MAJOR: principle removal, redefinition, or incompatible governance change.
- MINOR: new principle or section added.
- PATCH: clarification, wording, typo fix.
